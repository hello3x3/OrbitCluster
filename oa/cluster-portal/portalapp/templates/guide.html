快速入门

申请计算资源、连接容器、保存实验环境。也可以使用终端工具，让 Codex 等 agent 完成同样的用户操作。

首次使用

  1. 向管理员获取账号和初始密码，连接实验室网络后登录平台。
  2. 点击右上角头像，进入“个人资料”，修改初始密码。
  3. 添加连接容器的电脑上的 SSH 公钥：复制 .pub 文件的整行内容。只上传公钥，私钥留在自己电脑上。

还没有密钥时，在本机终端生成：

ssh-keygen -t ed25519
cat ~/.ssh/id_ed25519.pub

如果提示已有同名密钥，保留原文件或换一个文件名。添加公钥后即可申请资源，SSH 端口由平台自动分配。

申请与连接

打开“申请资源”，按页面顺序填写：

项目怎么选
任务名称3–10 个字符，同一账号下不能重复，不区分大小写
账户选择本次任务使用的账户；只有一个时自动使用
镜像首次可选公共镜像；已有环境可选个人镜像
套餐按实验需要选择 CPU、GPU 和内存规格
时长不超过所选套餐上限
节点一般保留“自动分配”；需要指定机器时再选择

提交后回到“我的资源”：

  • 排队中：等待调度分配资源。
  • 启动中：容器和 SSH 服务正在准备，稍后再连接。
  • 运行中：点击“连接/详情”，复制 SSH 命令，在本机终端执行。

连接时使用已登记公钥对应的私钥，平台密码不用于容器 SSH 登录。连接失败先打开“日志”查看启动信息和门户操作结果。

任务停止后名称仍被记录占用；删除已结束记录后，才可以再次使用该名称。

运行环境与存储

本系统以容器为核心：每个资源都是一个独立容器，代码、训练和调试都在容器内进行；镜像决定环境，保存镜像用于保留修改。

容器默认以普通用户身份运行。需要安装系统包/CUDA toolkit 时，在容器内执行：

unshare -Ur --map-root-user bash
whoami          # root
apt-get update

这个 root 仅限容器内的用户命名空间，不是宿主机 root。镜像 rootfs 展开后 su 没有 setuid 位，不能用来切换 root，也没有可用的 su root 密码；日常仍建议用普通用户，只有装系统包时才进入这个 root shell。

enroot 展开 rootfs 后文件归提交者所有，所以普通用户执行 apt-get update 通常能成功；但 apt-get install 会调用 dpkg，普通用户会报 requested operation requires superuser privilege。安装包请用上面的 unshare root。

基础容器已预装 Miniconda，位置是 /opt/miniconda3。进入容器后可直接使用：

source /opt/miniconda3/etc/profile.d/conda.sh
conda --version
conda create -n myenv python=3.11
conda activate myenv

不需要在自己的家目录里再安装一份 Miniconda。Conda 环境建议建在容器内的 /opt/miniconda3 下；需要长期保留时，把容器保存为个人镜像。

家目录 /share/home/<用户名> 建议只存放代码和小型配置。不要在 home 里保存大型数据集、conda 环境、checkpoint 或大量结果文件；这些内容会占用你的 NFS 配额，也会影响节点性能。

需要的数据请直接从只读 NAS 挂载（/mnt/nas/...）读取，不要把整个数据集复制到 home。代码和少量重要文件放在 home 会持久保留；容器内安装的软件环境请用「保存镜像」保留。

保存环境与结束任务

安装软件或修改环境后，想下次继续使用时：

  1. 在运行中的资源上点击“保存镜像”，填写名称并确认。
  2. 等待资源行显示保存成功，打包可能需要几分钟。
  3. 在“我的镜像”确认新镜像已出现，再按需要停机。

保存的是容器文件系统，不保存进程、内存或挂载目录中的实验数据。重要数据请写入管理员指定的持久存储目录。
单个个人镜像上限为 20 GiB：保存前检查容器 rootfs，导出后再检查镜像文件；超限会拒绝。不要把 ckpt、大数据或大量临时文件放在容器根目录；到期自动保存失败时会放弃保存并停机。

操作结果
停机取消当前作业、释放资源；不会先自动保存环境
重新启动按原参数和原镜像重新提交，端口重新分配；不恢复未保存的修改
删除删除已结束资源记录和对应作业日志，不等同于删除个人镜像

到期自动保存默认关闭：资源到期后会直接停机，不生成 auto_ 镜像；需要保留环境请在到期前手动「保存镜像」。管理员可在 /etc/cluster-portal/site.conf 设置 AUTO_SAVE_ON_EXPIRE=1 开启。被抢占的作业不会自动保存。

管理镜像

公共镜像由管理员维护，普通用户只读；个人镜像来自你保存的容器环境，存放在站点镜像目录（本站为 /images 独立盘，不占用 /share 家目录配额）。单个个人镜像上限 20 GiB。

个人镜像可以编辑注释、重命名和删除。镜像被排队任务使用时不能重命名；被排队或运行中的任务占用时不能删除。删除镜像后，引用它的旧资源无法再直接“重新启动”。

再次使用保存的环境：打开“申请资源”，在镜像下拉框的“我的镜像”分组选择它。

集群、额度与资料

  • 集群 → 集群占用情况：按分区和 GPU 型号查看节点 CPU、内存、GPU 的空闲/总量，采用 Slurm 调度口径。
  • 集群 → 门户内活跃资源：查看通过本门户提交的活跃任务及截止时间。
  • 我的资源 → 我的配额 / 额度：磁盘用量、硬上限，以及账户的优先级和单用户 GPU 上限。
  • 个人资料：管理 SSH 公钥、显示名和平台密码。修改密码后，旧终端凭证失效，需要重新登录。

额度、套餐、账户归属和账号状态由管理员维护。上限不足或账户不可用时，请联系管理员。

角色权限对照

下表只比较普通用户和非 root 的平台管理员；root 超级管理员不在此表，root 专属能力不向普通管理员开放。

功能普通用户管理员（非 root）
登录、个人资料、SSH 公钥、改密码✅✅
自助申请资源✅✅（需有同名 OS 账号；纯门户管理员不能申请）
管理自己的资源：连接、日志、停机、重启、删除✅✅
查看公共镜像和自己的镜像✅✅
管理自己的个人镜像：注释、改名、删除✅✅
查看集群占用、活跃资源和自己的额度✅✅
代申请资源—✅ 可代普通用户，也可代自己；不能代其他管理员
开通普通用户—✅
重置/停用/删除普通用户、修改普通用户配额—✅
授予/撤销管理员、创建管理员账号——（root 专属）
管理账户/QoS/优先级/单用户卡数上限、账户成员——（root 专属）

常见问题

为什么不能提交申请？
确认已添加 SSH 公钥，任务名没有重复，时长不超过套餐上限，且所选账户仍有效。
为什么一直排队？
可能暂时没有满足套餐、节点或账户限制的资源。查看“集群占用情况”；不要反复提交相同任务。
SSH 连接不上？
确认资源已运行，使用最新“连接/详情”里的命令，网络能访问节点，并持有对应私钥。重新启动后端口会变化。
镜像保存失败？
先查资源日志和磁盘配额。确认保存成功前，不要把停机当作已保存。
终端登录过期？
重新执行 orbit login --username 你的用户名。调整本机时间不能延长有效期。

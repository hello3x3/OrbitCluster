# 00 用生成器部署（改参数 → make → 下发）

> **最短路径**：整个集群（底层 Slurm/enroot + 门户）的机器配置与站点配置，全部由
> `provision/cluster.conf` **一个文件**生成。你只改那个文件，`make`，然后按生成出来的
> `MANIFEST.md` 下发。
>
> 想逐条理解原理与验收命令，再读 `base-cluster/all-in-one-cluster-manual.md`（底层，1–8 章）
> 与 `oa/01-部署手册.md`（门户）；本文只讲**怎么用生成器把它做完**。

## 0. 前提（生成器不做，必须先有）

| 事项 | 去哪做 |
|---|---|
| Ubuntu 24.04 Server、静态 IP / 主机名 / 互访 | 底层手册 1.2–1.3 |
| NVIDIA 驱动（`nvidia-smi` 正常） | 底层手册 1.4 |
| 共享盘：`SHARE_DEVICE` 分区/挂载、NFS 两端就绪 | 底层手册第 2 章（`/etc/exports`、`fstab` 行由生成器给） |
| Slurm 源码编译 + munge 密钥分发 | 底层手册 3–4 章（`slurm.conf`/`slurmdbd.conf` 等由生成器给） |
| enroot / pyxis / `nvidia-container-cli` 安装 | 底层手册 5.4–5.5（GPU 钩子文件由生成器给） |
| 容器镜像 `.sqsh` 放进 `<IMAGES_MOUNT>` | `base-cluster/images/README.md` |

> 建议顺序：**先按底层手册把"装包 / 编译 / 密钥 / 驱动"做完，再用生成器下发配置** —— 这样配置一落地就能直接起服务、跑验收。

## 1. 改参数：唯一的输入是 `provision/cluster.conf`

| 键 | 含义 | 备注 |
|---|---|---|
| `CLUSTER_NAME` / `ACCOUNT` | Slurm 集群名 / 会计账户名 | `ACCOUNT` 与 `add-user.sh` 的 `CLUSTER_ACCOUNT` 一致 |
| `LAN_CIDR` | 内网网段 | NFS 导出与 chrony 放行用 |
| `SSH_PORT` | 节点间 sshd 端口 | 非 22 就写上（自动进"用户不可申请的保留端口"） |
| `TIMEZONE` / `USER` | 时区 / 文档示例里用的用户名 | |
| `SHARE_DEVICE` / `SHARE_MOUNT` | 共享盘设备与挂载点 | 例：`/dev/sda` / `/share` |
| `IMAGES_DEVICE` / `IMAGES_MOUNT` | 镜像盘（留空=与共享盘同一块）/ 镜像目录 | 独立 NVMe 时填 UUID |
| `SLURM_VERSION` / `PARTITION` / `GRES_MODE` / `GPU_PREFIX` | Slurm 版本 / 分区名 / gres 模式 / 型号前缀 | `GRES_MODE=auto`（`AutoDetect=nvml`）或 `explicit` |
| `PORTAL_PORT` | 门户监听端口 | |
| `NODE` 行 | 节点清单：`名字=IP role=mgr,gpu\|gpu gpus= gpu_model= cpus= mem_mb= sockets= threads=` | **第一行 = 管理节点**（可兼计算），其余按顺序编号 `<GPU01>…` |

- `cpus` / `mem_mb` 用各机 **`slurmd -C` 实测值**；留空会渲染成 `@@待实测@@` 占位符，并在 `MANIFEST.md` 里列为"待回填"。
- 想临时试参数不必改文件：`make SET="SSH_PORT=2222 USER=alice"`。
- 想换一套集群：复制一份 conf（如 `provision/conf/3090-2node.conf`）后 `make CONF=provision/conf/<你的>.conf`。

## 2. 生成

```bash
make out        # ★ 推荐：不动仓库，产物自包含（含 docs/ 与 opt/cluster-admin/）到 provision/out/
make            # 就地：机器配置写到仓库根的 deploy/，同时把仓库里的文档就地填成你的实值
make print      # 先只打印，不落盘
make check      # 打印"需要人工核对"的清单
make reset      # 撤销就地替换，还原仓库模板
make sites      # 渲染两套回归夹具，验证生成器本身（与真机逐项对照用）
```

产物（以 `make out` 为例）：

```
provision/out/
├── MANIFEST.md                 ← ★ 下发清单：哪台机器放哪些文件、权限要求
├── etc/**                      ← 与目标机路径一一对应（25 个文件）
├── opt/cluster-admin/*.sh      ← 建号/配额三脚本
└── docs/**                     ← 文档的实值版（占位符已填成你的真实值，可直接交给部署人员）
```

> ⚠️ 就地模式（`make`）会把 `README.md`、`base-cluster/**/*.md`、`oa/**/*.md` **改写成你这套集群的实值** ——
> 不要把渲染结果 `git commit`。要回到模板：`make reset` 再重新 `make`。

## 3. 下发（按 `MANIFEST.md` 分角色）

### 3.1 每台节点（全部节点，内容相同）

```bash
for n in <ADMIN> <GPU01> <GPU02>; do      # 按你的 NODE 清单增减
  rsync -a provision/out/etc/hosts.$n          root@$n:/etc/hosts
  rsync -a provision/out/etc/slurm/            root@$n:/etc/slurm/
  rsync -a provision/out/etc/enroot/           root@$n:/etc/enroot/
  rsync -a provision/out/etc/tmpfiles.d/       root@$n:/etc/tmpfiles.d/
  rsync -a provision/out/etc/systemd/system/   root@$n:/etc/systemd/system/
  rsync -a provision/out/etc/ssh/sshd_config.d/ root@$n:/etc/ssh/sshd_config.d/
  ssh root@$n 'chmod 755 /etc/enroot/hooks.d/95-slurm-gpus.sh'   # enroot 只执行 +x 的钩子
done
```

覆盖：`hosts`、`slurm.conf`、`gres.conf`、`cgroup.conf`、`plugstack.conf`(+`conf.d/pyxis.conf`)、
`enroot.conf`、`hooks.d/95-slurm-gpus.sh`、`tmpfiles.d/{enroot,pyxis}.conf`、
`slurmd.service.d/20-wait-remote-fs.conf`、`sshd_config.d/10-portal-only.conf`。

### 3.2 仅管理节点 `<ADMIN>`

```bash
rsync -a provision/out/etc/exports                    root@<ADMIN>:/etc/exports
rsync -a provision/out/etc/slurm/slurmdbd.conf        root@<ADMIN>:/etc/slurm/
rsync -a provision/out/etc/mysql/                     root@<ADMIN>:/etc/mysql/
rsync -a provision/out/opt/cluster-admin/             root@<ADMIN>:/opt/cluster-admin/

# 下面两项是"追加行"，不是整文件替换（系统盘行要保留安装器原文）
cat provision/out/etc/fstab.<ADMIN>                 | ssh root@<ADMIN> 'cat >> /etc/fstab'
cat provision/out/etc/chrony/chrony.conf.append.mgr | ssh root@<ADMIN> 'cat >> /etc/chrony/chrony.conf'

ssh root@<ADMIN> 'chmod 600 /etc/slurm/slurmdbd.conf'     # 内含口令，仅 root 可读
```

门户的站点配置（`etc/cluster-portal/`）**不要手工 cp** —— 交给第 4 节的 `install.sh` 安装，
它会设好 `/etc/cluster-portal/` 的属主与权限。

`slurmdbd.conf` 的 `StoragePass` 填 `/root/.slurmdbd.pass`（600）里的口令；MariaDB 调优
（`99-slurm.cnf`）已在 `etc/mysql/` 里。`/opt/cluster-admin/` 同时要给各计算节点一份
（建号要三节点同步）。

### 3.3 仅计算节点

```bash
for n in <GPU01> <GPU02>; do
  cat provision/out/etc/fstab.$n                       | ssh root@$n 'cat >> /etc/fstab'
  cat provision/out/etc/chrony/chrony.conf.append.gpu  | ssh root@$n 'cat >> /etc/chrony/chrony.conf'
done
```

### 3.4 让配置生效

```bash
# 每台节点
systemctl daemon-reload && systemd-tmpfiles --create
systemctl restart chrony slurmd
# 管理节点
systemctl restart chrony nfs-server mariadb slurmdbd slurmctld
sinfo && scontrol show node          # 期望：各节点 idle，Gres 与本机 `slurmd -C` 一致
```

## 4. 部署门户（管理节点）

```bash
rsync -a oa/cluster-portal/ /tmp/cluster-portal-src/
bash /tmp/cluster-portal-src/deploy/install.sh \
     /tmp/cluster-portal-src <PORTAL_PORT> provision/out/etc/cluster-portal
```

第 3 个参数是**站点目录**（含 `site.conf` + `plans.json`，就是刚才下发的 `etc/cluster-portal/`）：
install.sh 会创建 `portal` 账号与数据目录、`/usr/local/sbin/portal-ctl` 与 sudoers 白名单、
systemd 单元，并创建默认管理员 `root`（初始密码落盘 `/root/.cluster-portal-admin`，600）。

**还要手工补两件生成器不猜的事**：

- **镜像**：把 `.sqsh` 放进 `<IMAGES_MOUNT>`（门户按 `*.sqsh` 自动扫描，无需登记）。
- **NAS/数据集透传**：编辑 `/etc/cluster-portal/site.conf` 加 `EXTRA_MOUNTS=<宿主路径>[:<容器内路径>][:ro|rw]`
  （可多行），**同时**在宿主节点 `/etc/fstab` 真的挂上；改完 `systemctl restart cluster-portal`。

详见 `oa/01-部署手册.md`（§2.1 site.conf 全字段、§2.2 NAS、§2.3 EXTRA_MOUNTS）。

## 5. 验收

| 层 | 命令 | 期望 |
|---|---|---|
| 门户自检 | `bash oa/scripts/verify-install.sh <PORTAL_PORT>` | 全 `[OK]`（含沙箱、配额、sshd 白名单、保留账号检查） |
| 门户安全 | `bash oa/scripts/e2e_security.sh`（管理节点 root，无参数） | 用户能进自己的容器、**不能**登宿主机 |
| 端到端 | `E2E_MGT=<ADMIN> E2E_PEER=<GPU01> python3 oa/scripts/e2e_verify.py` | 27 项断言全过（建号 → 申请 → ssh 进容器看卡 → 停机 → 删号无残留） |
| 底层 | 底层手册各章验收命令 + `nvidia-smi` / `sinfo` / 一次容器冒烟 | 见手册 |

> `oa/scripts/e2e_accounts.py` 不是命令行工具，而是上面这两个端到端脚本共用的**测试账号守卫**
> （保留 UID 段 59000–59999，成功失败都清理，并断言清理干净）。

## 6. 生成器不做什么（这些仍需按底层手册执行）

静态 IP/netplan、NVIDIA 驱动、munge 密钥分发、Slurm/enroot/pyxis 的**安装与编译**、
各类密码（`slurmdbd.conf` / 门户密码文件）、`.sqsh` 镜像的构建与导入。

它们**用到的配置文件**都已由生成器给出（见 `MANIFEST.md`）；生成器只生成文件，
不 ssh、不安装、不改任何机器状态。

## 7. 出问题先看这里

| 现象 | 处理 |
|---|---|
| 渲染报"待实测" | `cluster.conf` 的 `cpus`/`mem_mb` 没填：`slurmd -C \| head -1` 取值回填后重跑 `make` |
| 节点 `IDLE+DRAIN+INVALID_REG` | `slurm.conf` 的 `Gres=` 与 `gres.conf` 不一致；`GRES_MODE=auto` 的长型号名（如 `nvidia_geforce_rtx_3090`）改用 `explicit` |
| 容器里看不到 GPU | 钩子没执行：确认 `/etc/enroot/hooks.d/95-slurm-gpus.sh` 是 **755**，且节点装了 `nvidia-container-cli` |
| 作业起不来、报挂载错误 | `--container-mounts` 的宿主路径必须在**每台**节点上真实存在 |
| 改了参数但机器没变 | 生成器只产出文件；要重新下发并重启对应服务（第 3.4 节） |
| 想确认"生成物 vs 真机" | `make sites` 渲染两套回归夹具，逐项对照；差异会被 `provision/README.md` 的自检表记录 |
